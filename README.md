 Change Request: Обновление CMS на учебном сайте

  Цель изменения
**Обновление системы управления контентом (CMS) учебного сайта до последней стабильной версии** для повышения безопасности, исправления известных ошибок и обеспечения совместимости с новыми плагинами.

---

 Риски и меры по их минимизации

| Риск | Уровень риска | Меры минимизации |
| :--- | :---: | :--- |
| Нарушение верстки или логики сайта после обновления | Высокий | Тестирование обновления на локальной копии (dev-окружении) перед продакшеном |
| Сбой базы данных при миграции | Средний | Создание полного дампа БД непосредственно перед началом работ |
| Несовместимость текущих плагинов/тем с новой версией CMS | Средний | Предварительная проверка документации плагинов на совместимость |
| Доступность сайта для пользователей во время технических работ | Низкий | Проведение работ в часы наименьшей активности; включение режима обслуживания (Maintenance mode) |

---

  План работ

 Подготовительный этап
- [ ]  Оповестить пользователей о проведении технических работ
- [ ] Включить режим обслуживания (Maintenance mode) на сайте
- [ ] Создать полную резервную копию файлов сайта
- [ ] Создать резервную копию (дамп) базы данных

 Этап обновления
- [ ] Проверить соответствие серверного окружения (версия PHP/MySQL) требованиям новой CMS
- [ ] Запустить процесс обновления CMS через панель управления или CLI
- [ ] Обновить установленные плагины и темы до совместимых версий

 Этап проверки (QA)
- [ ] Проверить доступность главной страницы и основных разделов
- [ ] Проверить корректность работы административной панели
- [ ] Провести тестовую отправку форм и авторизацию пользователей
- [ ] Отключить режим обслуживания

---

  План отката (Rollback Plan)

<details>
<summary><b></b></summary>

В случае критических ошибок на этапе обновления или проверки, которые невозможно устранить в течение 15 минут, выполняется полный откат к исходному состоянию:

1. **Остановка процесса:** Прекратить любые активные операции по обновлению.
2. **Очистка поврежденных данных:** Удалить файлы новой версии CMS и очистить базу данных, если в нее были внесены некорректные изменения.
3. **Восстановление файлов:** Развернуть резервную копию файлов сайта из созданного бэкапа.
4. **Восстановление базы данных:** Импортировать дамп базы данных, созданный перед началом работ.
5. **Проверка работоспособности:** Убедиться, что сайт вернулся в исходное рабочее состояние (предыдущая версия CMS).
6. **Отключение режима обслуживания:** Открыть доступ для пользователей и перенести работы на другую дату для анализа причин сбоя.

</details>
